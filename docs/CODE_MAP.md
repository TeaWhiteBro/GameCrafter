# Code map

| Area | Entry files | Responsibility |
|---|---|---|
| CLI and policy | `pipeline.py`, `game_pipeline/cli.py`, `workflow.py` | Input normalization, current production contracts, dependency DAG and commands |
| Execution and recovery | `game_pipeline/core.py`, `implementation.py`, `diagnostics.py`, `repair_contract.py` | SQLite journal, hashes, scoped invalidation, diagnosis and evidence-bound repair |
| Design and source services | `game_pipeline/services.py`, `planning_agents.py`, `image_gateway.py`, `environment_assets.py`, `public_surfaces.py` | Model roles, concept generation/edit, Tripo tasks, public matched PBR and resource handoffs |
| Source preparation | `game_pipeline/local_adapters.py`, `adapters/blender/inspect_character.py`, `character.py`, `skin_quality.py` | Anatomy inspection, cleanup, weights, deformation poses and environment-source preparation |
| Scene construction | `adapters/blender/exploration.py`, `game_pipeline/planning_agents.py`, `production_readiness.py` | Configurable geometry, branching routes, support/collision contracts and structural whitebox |
| Native integration | `adapters/unreal/`, `game_pipeline/local_adapters.py`, `templates/Source/` | Project creation, imports, IK retargeting, materials, lighting and C++ runtime |
| Capture and validation | `game_pipeline/production_capture.py`, `dataset.py`, `capture_dataset.py`, `templates/Source/` | Full condition probes, independent calibration, paired channels and export checks |
| Configuration | `config/production_rules.json`, `public_surfaces.json`, `machine.example.json` | Theme-independent process constraints, source menus and local machine template |
| Packaging and tests | `scripts/build_release.py`, `verify_repository.py`, `tests/`, `.github/workflows/tests.yml` | Allowlisted export, source audit, offline regressions and clean-export CI |

The internal Python import namespace is `game_pipeline`. Public branding, figures, task templates and native integration variables use GameCrafter. Stage names are stable contracts; files generated by a run are referenced through manifests rather than hard-coded paths.

See [PLUGINS.md](PLUGINS.md) for provider replacement and [WORKFLOW.md](WORKFLOW.md) for precise named stages.

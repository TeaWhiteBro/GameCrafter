# Complete framework workflow

The framework fixes responsibilities, interfaces, recovery and acceptance. Character identities, map layout and visual theme remain inputs. The default profile is `world_demo`; `arena_demo` explicitly omits exploration and its capture sequences.

The bootstrap design call writes `GameSpec`. The production DAG is generated by `game_pipeline.cli.graph()` and saved in each run's `pipeline_manifest.json`. Use [the complete system diagram](workflow.html) to see the primary handoffs and select any of the 26 named stages for its exact dependencies. The [vector figure](workflow.svg) is suitable for presentations; the [exact DAG](workflow_dag.md) retains every declared edge. Machine prerequisites and executing-agent launch observation sit outside the production DAG.

Regenerate the figure, offline inspector and Mermaid dependency listing from `docs/workflow_graph.json` with `python scripts/draw_workflow.py`. The generator checks complete stage coverage; it does not run paid generation, Blender or UE. First run `python scripts/sync_workflow_graph.py` to synchronize all dependencies from `game_pipeline.cli.graph()`. A regression test checks that the published graph matches executable code.

## Recovery is part of the method

Each node consumes JSON configuration, named dependency results and local tool configuration. It returns a JSON result plus `_files`. The executor verifies/hashes those files before committing completion. SQLite stores state, costs/call reservations, remote IDs and failures. One writer owns a run; projects and artifact revisions are isolated.

Failures do not authorize substituting an unrelated accepted level. Classify the failure: source anatomy → mesh/rig; ungrounded platform → geometry/layout; black single-sided advertisement → winding/import; wrong spatial material mask → final UE coordinate basis; invalid clip → animation/runtime; shifted semantic/depth frame → capture/export. Repair that stage, preserve failed evidence and rerun affected consumers.

An uncertain visual interpretation requires another grounded view or geometric diagnostic. Resubmitting unchanged rejected images cannot yield a new acceptance. Three unsuccessful preflights produce a diagnosis worklist. The executing agent batches structural fixes; the bounded automatic loop adjusts only allowed exposure/sky/fog fields. Neither may waive a hard gate.

## Software boundaries

Tripo supplies distinctive source geometry, not guaranteed clean animation topology or traversable buildings. Blender authors the shared spatial contract for detailed and structural geometry. UE evaluates animation, gameplay, visibility and rendering. A trained language model plans/reviews; deterministic code validates measurable contracts; Codex handles scoped repairs. These roles are not synonymous with independent simultaneously running processes.

Character and scene branches are logically independent until UE integration, but the current executor runs stage nodes sequentially. Environment source submissions can overlap remotely. Reuse of hashes or compiled runtime code is an execution optimization, not permission to reuse previous-case game content in fresh mode.

## Standard delivered conditions

- `world_demo`: first, third and isometric cameras × combat and exploration = six active sequences.
- Every sequence contains RGB, depth, semantics, skeleton and structural whitebox. Default 360 frames at 640×360, simulated at 60 Hz.
- Real-time play targets 60 FPS and is measured separately from offline GPU readback/write throughput.
- Full-map walkability and sampled clip coverage are separate claims. Six-second samples do not prove exhaustive state coverage.
- Whitebox pairs share scene, camera and time but use simplified geometry; their exact silhouette boundaries are not identical to RGB.

See [QUALITY_GATES.md](../QUALITY_GATES.md), [DATASET.md](../DATASET.md), and [limitations](LIMITATIONS.md).


## Evidence-bound repair

`diagnose` summarizes failures and worklists without launching tools. `impact` previews implementation consumers. After three distinct environmental refusals, the next review requires complete issue coverage, latest-refusal/source fingerprints and hashed targeted evidence. Every requested full camera/activity job passes early, with exploration player visibility; matching immutable exports feed final collection after independent calibration and are reread during final pair checks.
